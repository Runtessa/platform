# IdpCore

**کد برنامه را تغییر بده؛ پلتفرم به کارش ادامه می‌دهد.**

IdpCore یک پلتفرم قابل نصب روی زیرساخت خودتان برای ساخت برنامه‌های چندمستاجری
است. ماژول‌های بک‌اند، مدل‌های پایگاه داده و رابط‌های React را در IDE می‌نویسید،
پیش‌نمایش می‌گیرید و منتشر می‌کنید. Core نسخهٔ انتخاب‌شده را هنگام درخواست اجرا
می‌کند؛ تغییر کد مستاجر به بازسازی یا راه‌اندازی مجدد پلتفرم نیاز ندارد.

## قابلیت‌ها

- ماژول‌های HTTP با JavaScript و TypeScript، مسیرها و دسترسی‌های مختص هر مستاجر.
- مدل‌های بومی TypeORM، متدها، روابط و عملیات صریح تغییر ساختار دیتابیس مستاجر.
- بسته‌های رابط React و بارگذاری آن‌ها با Kernel در مرورگر.
- پیش‌نویس، پیش‌نمایش، انتشار، بازبینی نسخه‌ها و پروژه‌های مشترک بک‌اند و رابط.
- آداپتورهای داده و سرویس‌ها با مجوزهای تعیین‌شده برای مستاجر.
- سرویس Auth برای ورود، هویت و اتصال ورود یکپارچهٔ مستاجرها.

نمونهٔ یک ماژول بک‌اند:

```js
module.exports = async function handler(req, adapters) {
  return {
    statusCode: 200,
    body: { message: 'Hello from live tenant code' },
  };
};
```

اجرای کد در پردازش‌های کوتاه‌عمر و محدودشده داخل Core و IDE انجام می‌شود؛ سرویس
اجرایی مستقل به معماری اضافه نشده است. کلیدهای پلتفرم در پردازش اصلی می‌مانند و
دسترسی کد به مستاجر و قابلیت‌های مجازش محدود می‌شود.

## شروع کار

محیط پشتیبانی‌شدهٔ اجرای زنده، لینوکس x86-64 یا arm64 با پشتیبانی از فضای نام
کاربر، Node نسخهٔ 22.13 به بالا در شاخهٔ 22 و bubblewrap است. برای نصب کانتینری
به Docker Compose یا Podman با ابزار Compose سازگار نیاز دارید. پایگاه دادهٔ
پلتفرم PostgreSQL 17 است.

```sh
git clone https://github.com/AlirezaDadrass/Idp.git
cd Idp
npm ci
npm --prefix src/auth ci
npm --prefix src/kernel ci
npm --prefix src/monitoring ci
npm --prefix src/container-agent ci
npm run docker:init-env
```

فرمان آخر رمزهای تصادفی و هماهنگ برای نصب جدید تولید می‌کند و تنظیمات کامل موجود
را تغییر نمی‌دهد. فایل‌های خصوصی را خارج از گیت پشتیبان بگیرید. ادامهٔ مراحل
ساخت، آماده‌سازی دیتابیس و اولین ورود در [راهنمای نصب](docs/getting-started.md) است.

Core و IDE هنگام شروع برنامه ساختار دیتابیس پلتفرم را تغییر نمی‌دهند. نصب جدید
نیاز به اجرای مهاجرت‌های صریح دارد؛ برای نصب موجود ابتدا نسخهٔ پشتیبان و بررسی
تطبیق ساختار لازم است. [راهنمای مهاجرت](scripts/database/README.md) این مسیر را
توضیح می‌دهد. Auth مسیر مهاجرت SQL جداگانهٔ خودش را دارد.

## وضعیت انتشار و محدودیت‌ها

پروژه در مرحلهٔ **پیش‌نمایش توسعه‌دهندگان** است. تست‌های دسترسی، ثبت امن خطا،
جداسازی اجرا و مهاجرت وجود دارند؛ این به معنی تضمین آمادگی هر نصب برای عرضهٔ عمومی نیست.

دسترسی شبکهٔ آداپتورها حفظ شده و محدودسازی مقصدهای شبکه و جلوگیری از SSRF باید در
محیط نصب اعمال شود. سقف حافظهٔ V8، سقف کل حافظهٔ پردازش نیست؛ بودجهٔ واقعی حافظه،
CPU و فایل‌های موقت به تنظیمات زیرساخت نیاز دارد. نقش‌های دیتابیس آداپتورها باید
فقط به دادهٔ مستاجر مربوط دسترسی داشته باشند.

پیش از استفادهٔ اینترنتی، سیاست امنیت، گزارش وابستگی‌ها، مسیر بازیابی پشتیبان و
آزمون کارایی را بررسی کنید. کلیدهایی که قبلاً افشا شده‌اند باید در سرویس مبدا
تعویض یا لغو شوند؛ حذف آن‌ها از تاریخچهٔ گیت کافی نیست.
